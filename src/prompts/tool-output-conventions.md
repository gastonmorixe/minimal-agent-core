# Tool output conventions

Every tool result whose body is large or got clamped by the universal 64KB / 1000-line cap also lands intact at `~/.minimal-agent/sessions/<sid>.blobs/<tool_use_id>.raw`. The agent appends a single line `<ma::agent::raw-output path="<abs-path>" size="<size>" sha256="<hex>" />` to `tool_result.content` whenever that file was written. Use `Read({file_path: "..."})` or `Bash({command: "wc -l '...'"})` on that path when the inline body is not enough: the file is the full pre-clamp, pre-annotation output. The clamp keeps the FRONT of the body, so when a command fails its trailing diagnostics are what got cut: Read the blob's tail to recover them. The blob also survives session resume, so a later turn can analyze the original bytes without re-running the tool. Small bodies under `minBytesToPersist` (default 4096 B) are not persisted and emit no footer; `content` is already complete.

When the user's transcript previewed fewer lines than you received, the agent appends a `<ma::agent::output-preview shown="N" total="M" tool="X">` annotation. If a raw-output blob was also written for that result, the annotation carries a `path="<abs-path>"` attribute (and the hint names it) pointing at the full output, so an elided preview always tells you where the rest lives.
